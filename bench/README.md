# On-board checks

Functionality and performance of the `tinymind` crate on two boards, mirroring
tinymind (C++)'s [framework comparison](https://github.com/danmcleran/tinymind/tree/master/benchmarks/framework_comparison_f411):
same boards, clocks, flash wait states, timing method, model weights and test
samples, so the numbers sit next to the tinymind (C++) ones.

| Board | Core | Clock | Timing |
|---|---|---|---|
| NUCLEO-F411RE | Cortex-M4F | 100 MHz, 3 wait states, ART on | DWT cycle counter |
| NUCLEO-L031K6 | Cortex-M0+ (no DSP, no hardware divide) | 32 MHz, 1 wait state, prefetch on | SysTick with wrap interrupt (no DWT on M0+) |

`src/board.rs` is a register-level port of tinymind (C++)'s `board/board.cpp` and
`board/board_l031k6.cpp`. Cycle counts are the median of 33 warm runs.

## Workloads

- **`mlp`**: tinymind (C++)'s int8 digits MLP (64-32-16-10, per-channel requantizers,
  ReLU fused into the requantizer) on `QDensePerChannel`, generated by `gen.py`
  from tinymind (C++)'s benchmark headers: the same int8 weights, requantizers and test
  samples (360 on the F411, the first 32 on the L031, as tinymind (C++) uses). The
  output hash over every sample must equal tinymind (C++)'s expected hash, which
  tinymind (C++) and TFLM both produce on these boards.
- **`xor-q16`, `xor-q8`**: tinymind (C++)'s xor example trained on the board, 20,000
  steps in Q16.16 and in Q8.8. The device hashes the exact bytes of the
  `nn_fixed_xor.txt` the example writes (every weight after every step) and
  compares with the golden hash in `tests/xor_golden.rs`.
- **`anomaly`**: the anomaly-detection demo (`examples/common/anomaly_demo.rs`,
  shared with `examples/anomaly.rs`): an 8-4-8 Q16.16 autoencoder trains on 3,000
  synthetic normal windows on the device, sets its threshold and screens 512 test
  windows. The report must equal the host's, and its hash (every trained weight
  and every score) must equal `EXPECT_HASH` in `src/anomaly.rs`, which the host
  run and `tests/anomaly_golden.rs` pin. No C++ counterpart.
- **`trees`**: the two imported scikit-learn models of the `imported_trees`
  example (gradient boosting, 90 trees on int8 inputs; random forest, 15
  voting trees on int16) classify the 54 held-out UCI Wine samples; the hash of
  every raw output and class must equal the host's (`EXPECT_HASH` in
  `src/trees.rs`). Both forms are timed, and the pool walk is timed from flash
  and from a copy in SRAM. The L031 image is built at `opt-level = "s"` to fit.
- **baseline** (no workload feature): the MLP harness with a do-nothing network,
  for size and stack deltas. **`profile`**: the MLP with per-layer timing.

## Results (2026-11-07)

Rust 1.99.1, `opt-level = 3`, LTO, one codegen unit. C++ figures are tinymind (C++)'s
own (`docs/benchmarks.md`, gcc 13.2.1 `-O3`), measured on these same boards.

### Exactness

| Check | F411 | L031 |
|---|---|---|
| int8 MLP output hash = tinymind (C++)'s (`0x85BDD037` / `0x06CE0530`) | match | match |
| xor Q16.16 training trajectory (20,000 steps) = golden | match | match |
| xor Q8.8 training trajectory (20,000 steps) = golden | match | match |
| anomaly demo: report and hash = host run (`0x427BACE2`) | match | match |
| MLP accuracy | 346/360 (96.11%) | 31/32 (96.88%) |

### Decision trees, imported from scikit-learn

Cycles for one prediction (median of 33), first held-out sample.

| | F411 | L031 |
|---|---:|---:|
| Correct on 54 held-out samples (gbdt / forest), hash matches host | 53 / 53, yes | 53 / 53, yes |
| Gradient boosting, pool walk (pool in flash) | 9,095 (91 µs) | 17,780 (556 µs) |
| Gradient boosting, pool walk (pool copied to SRAM) | 8,027 | does not fit |
| Gradient boosting, nested `if`s | 1,841 (18 µs) | 2,627 (82 µs) |
| Random forest, pool walk / nested `if`s | 2,024 / 462 | 3,936 / 820 |
| First 36 trees (256 nodes, 3 KB): flash / SRAM copy | 3,480 / 3,129 | 6,586 / 6,170 |
| `quantize_features` (13 float divisions) | 608 | 11,292 |
| Flash (text), whole image | 48,972 B | 32,520 B (opt-level s) |

- **Where the model is.** The node pools are immutable `static`s, so
  cortex-m-rt's linker script puts them in `.rodata`, in flash (the
  image reports the pool's address, in the 0x0800_0000 flash range); `.data` is empty and
  nothing is copied to SRAM at start-up. The CPU reads the pool from flash, as
  it reads every instruction.
- **Flash versus SRAM.** Reading the pool from flash costs 11-13% on the F411
  (three wait states at 100 MHz, mostly hidden by the ART accelerator's prefetch
  and caches) and 7% on the L031 (one wait state at 32 MHz). The 7.5 KB pool
  would not fit beside the stack in the L031's 8 KB of SRAM anyway.
- **The form matters far more.** The nested-`if` form is 4.4-6.8 times faster
  than walking the pool: it compares against constants in the instruction
  stream and has no loop or index arithmetic. The pool is the smaller form.
- **Placement.** The same gradient-boosting walk measured 14,044 cycles on the
  L031 in an image that differed only in an extra test; as with the int8 MLP,
  the M0+ with one wait state is sensitive to code placement.

### Reading these

- Exactness holds on both cores: the integer arithmetic and every training step
  match the C++ and the host bit for bit.
- Against tinymind (C++)'s scalar C++ the Rust port is 4% slower on the M4F and 7-18%
  slower on the M0+, at about the same size. It has no SMLAD path: the Arm DSP
  intrinsics are nightly-only and `asm!` would break `forbid(unsafe_code)`.
- On the M0+ the stack use is higher than the C++'s (472 B against 200 B).

## Run

```bash
python3 -I bench/gen.py 360     # or 32 for the L031; run.sh does this
bench/run.sh                    # both boards; or: bench/run.sh f411
WORKLOADS="anomaly" bench/run.sh f411 l031   # only some workloads
```

`run.sh` builds each image, records its size, flashes it with OpenOCD (ST-LINK
picked by serial number; override with `F411_STLINK` / `L031_STLINK`) and reads
the report from the ST-LINK's virtual COM port. Raw reports and images land in
`bench/results/` (not committed). CI builds every image but does not run them.
