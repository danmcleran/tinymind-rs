# Equivalence with tinymind (C++)

The acceptance test for every ported path is that it produces the same bits as the tinymind (C++) build. Not close results: identical files.

## What is compared

Eight of tinymind (C++)'s examples are ported, and every file they write must be byte-identical to the C++ example's output:

- **XOR**, in Q16.16 and Q8.8: stdout, the per-step weight trajectory (`nn_fixed_xor.txt`, about 20,000 lines), the learning curve and the decision surface.
- **Iris**: stdout, the loss curve, the per-sample test predictions and the confusion matrix. Its input is the dataset file tinymind (C++) ships with the example, checked byte for byte against tinymind (C++)'s copy.
- **Energy efficiency**: stdout, the loss curve and the per-sample test predictions of a regression (linear output, clipped gradients) on the UCI Energy Efficiency data, again read from tinymind (C++)'s own copy of the file.
- **Maze**: stdout, the path of every training and test episode of a Q-learner finding its way out of a six-room maze, and its final Q table beside the optimal one from value iteration.
- **Activity recognition** (`har_activity`): stdout, the loss curve, the synthesized sample windows and the test confusion matrix of an LSTM network trained on 800 windows of accelerometer data. The C++ is built with `-ffp-contract=off`, because the windows are synthesized in `double` and a compiler that fuses multiply-adds would change them.
- **Int8 XOR**: stdout and the decision surface of a PyTorch-trained network running in int8. tinymind (C++)'s int8 path matches TensorFlow Lite's reference kernels, so this also ties the Rust port to TFLite's arithmetic on these cases.
- **Int8 GBDT**: stdout, the predicted class over a 48 x 48 input grid and the compact golden report of a five-tree gradient-boosted ensemble quantized to int8.
- **Int8 KWS-shaped CNN** (`kws_cortex_m_int8`): its stdout carries host timings, so it is compared tensor by tensor instead (below).

Parts that no tinymind (C++) example exercises are compared through small C++ programs built on tinymind (C++)'s library (in `scripts/cpp/`), whose output must match the Rust port's in the same way:

- **Networks with several hidden layers**: tinymind (C++)'s `NeuralNetwork` with two and three hidden layers, in both formats, trained for thousands of steps, with a hash of every weight after every step; two regressions with a linear output and gradient clipping (one with an asymmetric range), sized so that clipping the weight and bias gradients changes the result; and runs with tinymind (C++)'s Adam and RMSprop optimizers on one, two and three hidden layers, in both formats.
- **Floating-point networks**: tinymind (C++)'s `NeuralNetwork` instantiated with `double` and `float`, with the floating-point activations and transfer-function bundle its float example and unit tests define (tanh, `1 / (1 + exp(-x))`), trained for 2,000 to 3,000 steps in nine configurations (one to two hidden layers; tanh and ReLU; sigmoid and linear outputs; SGD and its `AdamOptimizerFloat` and `RmsPropOptimizerFloat`), and its `LstmNeuralNetwork` in four (SGD and Adam), every weight hashed after every step: bit-identical on a glibc host, where both take tanh and exp from glibc. The `float` results depend on the glibc version (its `tanhf` and `expf` became correctly rounded in 2.41), so those are compared live on each machine; the `double` results also have a committed golden.
- **Inference-only networks**: tinymind (C++)'s networks built with `IsTrainable = false`, loaded with the same weights as the Rust `InferencePerceptron` (one hidden layer, two shapes) and `InferenceNetwork` (one to three hidden layers, five configurations); the trainable networks loaded with the same weights must agree too.
- **Int8 softmax**: tinymind (C++)'s TFLite-exact softmax and its calibration over 504 calibrations and row lengths from 1 to 511, plus the golden rows tinymind (C++)'s tests take from the TensorFlow Lite Micro reference kernel.
- **Int8 KWS-shaped CNN**: every tensor of tinymind (C++)'s `kws_cortex_m_int8` example (the quantized input, weight tables and requantizers from its calibration, and each layer's output) and its report of the int8 logits against the float model's, dumped by a program that compiles the example unchanged. The calibration runs the network in float, so this also checks that the float sums match bit for bit.
- **Int8 convolution and pooling**: tinymind (C++)'s `QConv2D`, `QConv2DPerChannel`, `QDepthwiseConv2D`, `QPointwiseConv2D`, `QPointwiseConv2DPerChannel`, `QMaxPool2D`, `QAvgPool2D` and `QGlobalAvgPool2D` over random tensors, in 57 configurations covering the code paths of its portable (non-SIMD) build, padding on every side and both requantizer paths.
- **Int8 addition**: tinymind (C++)'s `QAdd` and its calibration, `buildQAddParams`: 48 layers calibrated from random scales, run on every pair of int8 inputs, and 80 with random integer parameters, including sums that saturate the requantizer.
- **Int8 multiplication, concatenation and padding**: tinymind (C++)'s `QMul` with `buildQMulRequantizer` (32 calibrated layers on every pair of int8 inputs, 48 with random requantizers), `QConcat2_2D` with `buildRescaler` (five shapes) and `QPad2D` (six padding patterns).
- **Int8 recurrent cells**: tinymind (C++)'s `QLSTMCell` (int8 and int16 cell state) and `QGRUCell` with `buildQLSTMParams`, `buildQGRUParams` and the bias quantizers: seven LSTM and six GRU shapes, two trials calibrated from random float models and two with random integer parameters each, the hidden and cell state hashed after every step of 32-step sequences.
- **Q-learning**: tinymind (C++)'s `QLearner` with its Q table hashed after every update, on the maze example (in the unsigned Q16.16 the C++ example uses) and on 60 random environments in Q16.16 and Q8.8 with negative rewards, states with zero, one, two or more valid actions, learning rates and discount factors of exactly 1 and ones its setters must reject, and updates for a state other than the learner's current one.
- **LSTM networks**: tinymind (C++)'s `LstmNeuralNetwork` in seven configurations (Q16.16 and Q8.8; 1 to 16 cells; tanh or ReLU cell candidates; sigmoid or linear outputs; gradient clipping, including an asymmetric range; SGD and Adam) on sequences of 1 to 12 steps with the state reset between them, some steps not trained, and the outputs and every weight hashed after every step.
- **Decision trees**: tinymind (C++)'s `QDecisionTree` and `QGBDT` over 72 random ensembles with int8, uint8 and int16 thresholds, base scores, tied classes and inputs on the thresholds.
- **PyTorch importer**: the same models imported with tinymind (C++)'s importer and with this repository's, run on both runtimes: two dense networks (sigmoid, softmax) and two convolutional ones, whose comparison includes a hash of every intermediate tensor. On seven models, both importers also compute identical scales, zero points, weights and biases.
- **TFLite translator**: the MLPerf Tiny keyword-spotting model (DS-CNN) and image-classification model (ResNet-8, with residual additions), translated from their `.tflite`, give tinymind (C++)'s output hashes on 8 seeded inputs each (the hashes TFLite's reference kernels also give); its softmax parameters equal tinymind (C++)'s on 504 calibrations, and its addition parameters tinymind (C++)'s `buildQAddParams` on 48. Its padding, multiplication and concatenation, which those models do not use, are checked on small generated models against TFLite's own reference kernels (LiteRT): every output byte the same.
- **Tree importer**: 18 scikit-learn, XGBoost and LightGBM models imported with both importers must give identical integer trees, and each output must match on its own runtime; two models for the UCI Wine data run on both runtimes with byte-identical output.

Fixed-point arithmetic makes this demanding. A multiply truncates, so `(a * b) * c` and `a * (b * c)` can differ in the last bit, and one bit early in training becomes a different weight trajectory. The port keeps the C++ operation order in every expression, and repeats details that do not affect the result's quality but do affect its bits, such as a random draw the C++ makes for a connection it never uses.

## How it is checked

- **Golden tests.** `cargo test --all-features` runs the examples (xor in each format, iris, energy efficiency, maze, har_activity, int8 xor, the GBDT, the KWS-shaped CNN and the importers' models) and the comparisons above that have goldens, and checks their output against goldens produced by the C++ build; the importer parity checks, the TFLite translator and the live floating-point comparison run in `scripts/compare-with-cpp.sh` only. The goldens for everything ported come only from C++ runs, never from the Rust output, or the test would prove nothing. The anomaly-detection example has no tinymind (C++) counterpart, so `tests/anomaly_golden.rs` pins its own output instead: a regression check, and the hash the boards must reproduce.
- **Live comparison.** `scripts/compare-with-cpp.sh` builds the tinymind (C++) examples from a tinymind (C++) checkout with the flags their Makefiles use, and the C++ programs in `scripts/cpp/`, runs both sides and compares every output file: 76 checks today, including that `data/iris.data` and `data/ENB2012_data.csv` are still tinymind (C++)'s files. The Q8.8 xor build is tinymind (C++)'s example with its two bit-count constants set to 8; nothing else changes.
- **Pinned tinymind (C++) commit.** The file `TINYMIND_REF` records the tinymind (C++) commit the port was last verified against. CI checks out exactly that commit.
- **Arithmetic oracle.** Ported from tinymind (C++)'s own oracle: every `QValue` operation is checked against an exact integer reference, on edge values and a random sample for nine formats, and on every pair of operands for Q8.8, about 26 billion checks per pull request. That run keeps Rust's integer-overflow checks on, so an overflow that happens to give the right answer still fails. A nightly job repeats the sample with a fresh seed.
- **Proofs.** [Kani](https://model-checking.github.io/kani/), a model checker built on the same CBMC engine tinymind (C++) uses for its own proofs, checks properties for every possible input rather than a sample: that addition, subtraction and multiplication wrap and round exactly as specified, that division never panics, that tanh and sigmoid never index outside their tables or leave their range, that the int8 requantizer's fast path equals gemmlowp's two-step rounding, and that the requantizer, the int8 dense layers, convolutions, pooling, addition, multiplication, padding and concatenation, the tables, the softmax, the int8 LSTM and GRU cells, the decision trees, the Q-learner and the LSTM network never panic, whatever their parameters.
- **No reachable panics.** CI links a Cortex-M firmware image that calls every public function and has no panic handler, for Cortex-M0+ and M4F at three optimisation levels; a panic path that survives optimisation fails the build.
- **Tables.** CI regenerates the activation lookup tables from tinymind (C++)'s source and fails if they differ from the committed ones.
- **CI and branch protection.** Every pull request runs all of this, and a pull request cannot merge unless it passes. Each check was shown to fail on a deliberately planted defect before it was trusted.
