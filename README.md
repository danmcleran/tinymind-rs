# tinymind-rs

[![CI](https://github.com/danmcleran/tinymind-rs/actions/workflows/ci.yml/badge.svg?branch=master)](https://github.com/danmcleran/tinymind-rs/actions/workflows/ci.yml)

tinymind-rs (crate `tinymind`) brings [tinymind](https://github.com/danmcleran/tinymind),
a header-only C++ library for neural networks on embedded systems, to Rust. Like
tinymind, it is free, open source software under the MIT license. The library is
`no_std` and allocation-free, and every ported path is verified bit-for-bit
against the C++ build: the XOR example's weights, training log and decision
surface are byte-identical to the C++ output.

Documentation, including the API reference: <https://danmcleran.github.io/tinymind-rs/>

## Status

Early. So far the port covers what tinymind's XOR and iris examples use: Q16.16
and Q8.8 arithmetic, ReLU and lookup-table tanh and sigmoid activations, and a
trainable one-hidden-layer perceptron. The API is not stable yet, and the crate is not on crates.io yet.

The minimum supported Rust version is 1.85. CI builds the library for Cortex-M4F
(`thumbv7em-none-eabihf`) and Cortex-M0+ (`thumbv6m-none-eabi`).

## Quick start

```bash
cargo run --release --bin xor -- output                  # Q16.16, output files in ./output
cargo run --release --bin xor -- --format q8.8 output    # the same network in Q8.8
cargo run --release --bin iris -- output                 # iris species classifier (ReLU hidden layer)
cargo test                                               # golden tests against the C++ output
scripts/compare-with-cpp.sh                              # rebuild the C++ examples and diff everything
```

The `xor` binary takes an optional `--format q16.16|q8.8` (default Q16.16), an
optional output directory (default `output`), then an optional learning rate and
momentum. It writes `nn_fixed_xor.txt`, `xor_training.csv` and
`xor_decision_surface.csv` there and prints a summary on stdout. The `iris` binary
takes an optional output directory and data file (default `data/iris.data`, the
UCI Iris dataset under CC BY 4.0; see `NOTICE`) and writes `iris_loss.csv`,
`iris_scatter.csv` and `iris_confusion.csv`.

`scripts/compare-with-cpp.sh` needs a tinymind checkout and `g++`. It looks in
`../tinymind` unless `TINYMIND_DIR` is set.

## What is ported

| Rust | C++ (tinymind) |
| --- | --- |
| `src/qformat.rs` | `cpp/qformat.hpp`: `QValue`, Truncate and Wrap policies, `i32` and `i16` storage (`Q16_16`, `Q8_8`) |
| `src/activation.rs` | `cpp/activationFunctions.hpp`, `cpp/lookupTable.hpp`, `cpp/interpolate.hpp`: ReLU, tanh, sigmoid |
| `src/lut.rs` | `cpp/lookupTables.cpp`: Q16.16 and Q8.8 tanh and sigmoid tables, generated by `scripts/extract-luts.py` |
| `src/neuralnet.rs` | `cpp/neuralnet.hpp`: one-hidden-layer MLP, SGD with momentum, batch size 1 |
| `src/rand.rs` | a re-implementation of glibc `rand()`, which the C++ example uses for weight init and sampling |
| `src/bin/xor.rs` | `examples/xor/xor.cpp` |
| `src/bin/iris.rs` | `examples/iris/iris.cpp` |

Everything else in tinymind (floating-point networks, other Q formats, unsigned
and 8/64-bit storage, the other activations, recurrent layers, the int8 quantization tiers, SIMD
backends, and so on) is not ported.

## How equivalence is proven

- `tests/xor_golden.rs` runs the `xor` binary in each format and compares its
  stdout and the two CSV files byte-for-byte with the goldens in
  `tests/golden/<format>/`. The 2.4-2.6 MB `nn_fixed_xor.txt` is checked by
  length, line count and a 64-bit FNV-1a hash instead of being stored. The goldens
  come from the C++ build: Q16.16 from the example as shipped, Q8.8 from the same
  example with both bit counts in `xornet.h` set to 8. `tests/iris_golden.rs`
  does the same for iris against `tests/golden/iris/`. `TINYMIND_REF` records the
  tinymind commit they were last verified against.
- `scripts/compare-with-cpp.sh` builds the C++ examples from a tinymind checkout
  (xor in both formats, iris) with the flags their Makefiles use, runs both
  programs, and runs `cmp` on every output file. It also checks that
  `data/iris.data` is still tinymind's file. It exits nonzero if anything differs.
- `tests/qformat_oracle.rs`, ported from tinymind's qformat oracle, checks every
  `QValue` operation against an exact reference: edge values and a fixed-seed
  sample for nine formats, and every operand pair for Q8.8 (about 26 billion
  checks, run in CI with overflow checks on). A nightly job reruns the sample with
  a fresh seed.
- `scripts/extract-luts.py` generates `src/lut.rs` from tinymind's
  `cpp/lookupTables.cpp`; CI regenerates it and fails if the tables differ.
- CI runs all of these on every pull request (the `cpp-equivalence` job checks out
  tinymind at `TINYMIND_REF` for the compare script and the table check), and
  branch protection blocks merging unless they pass.
