## `src/qlearn.rs`, `examples/maze.rs`, `examples/common/maze_driver.rs`

C++ source: `cpp/qlearn.hpp` (`QLearner`, `QValueTablePolicy`, `ArgMaxPolicy`, `DefaultLearningPolicy`, `QLearningEnvironment`), `examples/maze`

2026-11-09. `QLearner<V, E, STATES, ACTIONS, Q = QTable>` owns its `Environment<ACTIONS>` (user trait: `valid_actions` fills a buffer, `random_int(min, max)` = the C++ RandomNumberPolicy's `randInt`) and its `QValues<V>` (open trait; `QTable { pub values: [[V; A]; S] }`, out-of-range get 0 / set ignored). States and actions are `usize`, invalid = `None` (C++ uses the type's max). Learning rate, discount (`< ONE`) and exploration percent (`<= 100`, the C++ example policy's check) live in the learner; initial 0 (the C++ example policy leaves the percent uninitialized). The C++ `environment.takeAction(experience)` hook is dropped (the maze only stores it). Since tinymind #261 (`1b310c0`, ported 2026-11-10): the update is for `experience.state` (Experience gained `state`; >= STATES updates nothing, whatever the learner's own state), the future Q is `Q(s', a*)` with a* = ArgMax over s''s valid actions (first valid action when all tie, 0 when none; never draws RNG), exploration draws `random_int(0, 99) < point` (exactly p/100), ArgMax with 2 actions treats a tie as no preference (random), rates are accepted in [0, 1] (`isInUnitInterval` = `!(v < 0) && !(1 < v)`, so NaN passes; negatives now rejected, 1 accepted); nothing computed when lr = 0. ArgMax with 3+ (since #258): first of the largest Q whatever its sign, random only when every valid action ties. The C++ maze uses unsigned Q16.16 (`QValue<16,16,false>`); the port uses signed `Q16_16` (all values non-negative, -1 reward only compared), proved by the sweep hashing the unsigned C++ table. C++ `Constants` has no float specialization, so its QLearner needs a Q format; ours also runs on f32/f64. maze since #261: 5000 episodes (decay over the last 100), Q* by value iteration in f64 (`maze_qtable.csv`, max |err| 0.00069), greedy test runs at lr 0; C++ built with -ffp-contract=off; stdout (571 KB) and training CSV pinned by FNV-1a in `tests/maze_golden.rs`. Checked by `tests/maze_golden.rs` and `tests/qlearn_sweep.rs` (golden from `scripts/cpp/qlearn_sweep.cpp`, UBSan clean: maze in UQ16.16 on the example's schedule + 60 random envs in Q16.16/Q8.8 with 0/1/2/3+ valid actions, negative rewards, lr/df 0, exactly 1, > 1, < 0, exploration 0/100/150/random with decay, every 4th episode starting with an update for a random or invalid (S) state, every 5th step followed by a replayed experience for a random state). Plants that fail it (2026-11-10): exploring bootstrap, learner's state instead of experience.state, (p+1)/101 draw, 2-action tie to a1, rate 1 rejected, negative rate accepted, all-tied bootstrap drawing a random action. Equivalent mutant: dropping the `state < STATES` guard (the table ignores out-of-range writes and the bootstrap draws nothing). Kani `qlearner_never_panics` (304 checks, ~4 s; planted `valid[index]` fails it and panic-never). **`QNetwork` (DQN, 2026-11-12, against `TINYMIND_REF` 4cccbcd)**: C++ `QValueNeuralNetworkPolicy` (#258 made `getQValue` feed the requested state; `examples/dqn_maze` one-hot input, linear output). Non-breaking: `QValues::q_value(&self)` is answered by a new crate-private `MultilayerPerceptron::evaluate(&self)` (the feed-forward sums without storing activations; unit-tested equal to `feed_forward` in `same_outputs`), so no RefCell and no change to the trait (`future_q_value(&mut self)` was already there). Holds the online `MultilayerPerceptron` and the target as an `InferencePerceptron` (weights only; the C++ keeps two trainable nets), `inputs: fn(usize) -> [V; IN]` (C++ static `getInputValues`), `target_update_interval` (C++ template param; `iterations >= interval` copies, so 0 copies every step like 1). `set_q_value`: feed forward, learned values, set the action's, train only if it differed; out-of-range action ignored. The C++'s cached forward pass (`mFedState`) changes no result. MLP only (the C++ is generic over NeuralNetworkType; `NeuralNetwork` would need its own `&self` evaluation). `dqn_maze` example: weights from libstdc++ `minstd_rand0(7)` + `uniform_real_distribution<double>(-1, 1)` (`generate_canonical<double, 53>`: 2 draws, log2 of the range truncated to 30) then `from_f64_trunc` (C++ `ValueConverter<double, Q>`); the C++ target net's own draws are skipped (nothing reads that generator afterwards). Matched stdout, stderr (empty) and all CSVs on the first run; C++ built with -ffp-contract=off (CI's g++ 15 contracts). `tests/dqn_maze_golden.rs` (stdout 1.1 MB and training CSV pinned by FNV-1a). Plants that fail it: lookahead from the online net, refresh one step late, train when equal, q_value from the target, target never refreshed. Kani `qnetwork_never_panics` (1-1-2 Q8.8 ReLU/linear, any weights/rates/states/actions/interval, 54 s; planted `targets[action]` fails it and panic-never). panic-never: 6-8-4 Q16.16 tanh/linear learner. Q values end within 0.00064 of Q* (RMS 0.00047), all test episodes shortest. Not ported: the importers do not emit DQNs (nothing to port)
