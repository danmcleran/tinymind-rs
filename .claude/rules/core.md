# Q formats, networks, optimizers and their examples

Porting notes moved out of CLAUDE.md (2026-11-11). They load when a file under
`paths:` is read. The Rust <- C++ map is the layout table in CLAUDE.md; add new
hard-won detail here, and new files to `paths:`.

## `src/qformat.rs`

C++ source: `cpp/qformat.hpp`, `cpp/typeChooser.hpp`, `cpp/include/tinymind_rounding.hpp`

SGD's rounded products: `mul_round_toward_zero` (#266, momentum terms) and `mul_round_nearest` (#267, `lr*g`; C++ `ShiftNearest`: ties away from zero; since 2026-11-13 `(p + half + sign) >> FRAC`, one add cheaper than rounding the magnitude, same results, numbers in `bench.md`), both branchless, provided `Scalar` methods (`*` for floats), Kani-proved for six formats; a ties-up plant fails Kani and the goldens. tinymind #265 (`d4f4514`) only constrained the C++ free operator templates to QValue operands (IsQValue; no arithmetic change) and fixed activations/layers not ported here (softmax classifier output, GELU, capped ReLU, Xavier normal, BatchNorm1D, BinaryDense): all comparisons identical, pin bump only (2026-11-10). `QValue<S, const FRAC: u32>` over `S` = `i32` (wide `i64`) or `i16` (wide `i32`); methods generated per storage type by `impl_qvalue!`, because stable Rust cannot pick a type from const-generic arithmetic (`QTypeChooser`); Truncate + Wrap policies only; `Scalar` trait (was `Fixed`, now a deprecated alias) = the implicit C++ "ValueType concept", implemented for the Q formats, `f32` and `f64`

## `src/neuralnet.rs`

C++ source: `cpp/neuralnet.hpp`

One-hidden-layer MLP, batch 1, default policies; plain arrays, no placement-new buffers. `InferencePerceptron` = C++ `IsTrainable = false`: a separate type holding only weights (no per-neuron state, `const fn new`, `feed_forward(&self)`), same sum order as the trainable one; checked by `tests/inference_mlp.rs` (golden from `scripts/cpp/inference_mlp.cpp`: tinymind's untrainable net loaded through its setters, 4 configs) and unit tests vs `MultilayerPerceptron`. Whole-matrix weight setters, not per-index (no panics)

## `src/network.rs`

C++ source: `cpp/neuralnet.hpp` (`NeuralNetwork`, chain path: `InnerLayerChainBuilder`, `ChainNetworkDeltasCalculator`, `ChainNetworkGradientsCalculator`, `ChainBackPropConnectionWeightUpdater`)

Any number of hidden layers: `NeuralNetwork<L>` over a flat tuple of 1-8 `Dense<V, A, IN, OUT>` (impls generated by `impl_layers!`; sealed `Layers` trait; sizes chained by the impl's const params). Rust has no variadic generics, so no `HiddenLayers<...>`. Per-layer activation (C++ uses one for all hidden layers). Init order = C++ by source layer (inputs then bias), then one draw per output neuron. Deltas all computed before any update; update order irrelevant (each connection reads only itself). Checked by `tests/deep_mlp.rs` (golden from `scripts/cpp/deep_mlp.cpp`: tinymind's `NeuralNetwork` with `HiddenLayers<4,4>`, `<8,6,5>`, `<8,6>`, both formats, every weight hashed after every step) and unit tests vs `MultilayerPerceptron` **Inference-only form** (2026-11-09): `InferenceDense<V, A, IN, OUT>` (pub `weights`/`bias_weights`, `const fn new`, `forward` in the C++ sum order like `Dense`) and `InferenceNetwork<L>` (pub `layers`, `const fn new`, `feed_forward(&self)`) over tuples of 1-8, sealed `InferenceLayers` generated by the same `impl_layers!`; `LayersImpl::Inference` (bound to the same Inputs/Outputs) with `to_inference`/`set_from`, exposed as `NeuralNetwork::to_inference`/`set_weights`. Checked by `tests/inference_deep.rs` (golden from `scripts/cpp/inference_deep.cpp`: tinymind's `NeuralNetwork<..., HiddenLayers<...>, ..., false>` loaded through its setters, 5 configs x 8 weight sets x 16 inputs, plus the trainable C++ net agreeing); plants (no activation, bias of neuron 0, set_from skipping biases, first input only) fail it

## `src/optimizer.rs`

C++ source: `cpp/adam.hpp`, `cpp/rmsprop.hpp` (`SquareRootApproximation` -> `qformat::Sqrt`; `AdamOptimizerFloat`/`RmsPropOptimizerFloat` -> `AdamFloat`/`RmsPropFloat`, see Floating point below)

Optimizer = type parameter (`Opt = Sgd`, zero-sized, so no size cost; `new` exists for `Sgd` only, `with_optimizer` for any). Sealed `OptimizerImpl` (allow `private_interfaces`: it takes the crate-private `Connection`). Since tinymind #264 (`a40979f`, ported 2026-11-10): `begin_step` once per `train` before any update (C++ `beginTrainingStep`; was `step()` per layer), Adam/RMSprop/AdamFloat/RmsPropFloat update biases through the optimizer (`update_bias` takes `clip`), SGD clips bias gradients too, fixed Adam keeps `powers: Option<(b1^t, b2^t)>` (None = t 0, so `const fn new` needs no `V::ONE`) and corrects when `1 - b^t > 0` (no t<100 cut-off, no epsilon threshold), AdamFloat keeps f64 products (`pow` gone from `float_math`). Weight decay under Adam is C++-only (weight decay is not ported). `Default` for `Adam`/`RmsProp` on `Q16_16`/`Q8_8` = C++ `QFractionLsbs`/`QAdamEpsilonLsbs` (Q16.16 Adam 58982/64881/2560, Q8.8 230/253/160; RMSprop 58982/1, 230/1; printed by a C++ program and pinned by a unit test; deep_mlp's Q8.8 runs use C++ `AdamOptimizer<Q8>`/`RmsPropOptimizer<Q8>` defaults and Rust `Default`). `GradientClipByValue<V, I, F>` is now `[-b, b]` with b = QValue(I, F), so the harnesses' asymmetric `[-1.5, 2.5]` runs use their own `AsymmetricClip` policy. Moments live in the delta-weight slots. `(1 - beta2) * g * g` is left-associative. Checked by the adaptive runs in `tests/deep_mlp.rs`, `tests/lstm_sweep.rs`, `tests/float_mlp.rs`; plants that fail (2026-11-10): t per layer, Adam/RMSprop/AdamFloat bias not updated, SGD bias not clipped, t<100 cut-off, epsilon threshold, AdamFloat via pow

## `src/head.rs`, `examples/gas_sensor_drift.rs`, `examples/common/gas_driver.rs`

C++ source: `cpp/densehead.hpp`, `cpp/prototypehead.hpp` (tinymind #277, `b0920b7`), `examples/gas_sensor_drift`

Ported 2026-11-13 at `3d89270`. `DenseHead<V, IN, OUT, L = SoftmaxCrossEntropyLoss>` stores `[[V; IN]; OUT]` (C++ flat `o * IN + i`, same order) with pub `weights`/`biases` (no per-index get/set: no panics); `train`/`train_class` take `Option<&mut [V; IN]>` for the C++ `inputDeltas` pointer; a class >= OUT gives an all-zero target, as in the C++. `PrototypeHead` ignores out-of-range classes in its mutators (C++: UB), `distance`/`prototype` return `Option`. `learn` divides with `div_int` (C++ `QValue / int` = `applyInteger`), not `/ from_int`. `SoftmaxExp` = C++ `detail::HeadExp`: exp table (new `EXP_Q16_16`/`EXP_Q8_8` in `src/lut.rs`, via `extract-luts.py`) with 0 at or below -6; for Q8.8 the table's first entry is already 0, so the -6 cut is an equivalent mutant there. Float softmax uses std/libm `exp`; the sweep has no f32 softmax (glibc 2.41 changed expf, see Floating point). `MultilayerPerceptron::hidden_values` added for the example's hidden-layer check. Checked by `tests/head_sweep.rs` (golden from `scripts/cpp/head_sweep.cpp`, 9 dense + 3 softmax + 7 prototype runs, integer LCG draws so Q formats and floats start from the same numbers, matched on the first run) and `tests/gas_golden.rs` (all 5 outputs, first run; 56 s debug, 4.3 s release; C++ 3.7 s at -O3). Plants that fail the sweep: Q16 exp cut at -7, weight or bias step floored, divide via reciprocal (prototype and softmax), Manhattan without abs, dense and prototype ties taking the last (needed the added tie lines), count past cap, set_prototype uncapped, cap 0 kept. Kani `mod head` (four proofs, 25 s): exp in [0, 1] and 0 at <= -6 (both formats), dense (both losses) and prototype never panic, counts <= cap, cap >= 1; plants (exp at -7, cap 0, set_prototype uncapped after the cap) fail. panic-never: `heads::<V>` for Q16.16, Q8.8, f32, f64 (an indexing plant in `learn` fails the M0+ link). On the boards (2026-11-13): bench workload `head`, see `.claude/rules/bench.md`.

## The first ported examples (written 2026-11-07)

- tinymind's `examples/xor` (2-4-1 MLP, Q16.16, tanh hidden + sigmoid output, SGD with
  momentum, 20000 steps) is ported and runs **bit-for-bit identically** to the C++
  build: the per-step weight trajectory (`nn_fixed_xor.txt`), learning curve,
  decision surface and stdout are byte-identical.
- tinymind's `examples/pytorch_quant/xor` (a PyTorch-trained 2-4-1 network
  quantized to int8: QDense, qrelu, QDense, sigmoid LUT) is ported as
  `examples/int8_xor.rs` (feature `std`) and bit-exact: stdout and the decision
  surface. Its requantizers and sigmoid table are built from float scales on the
  host; Rust's `f32::exp` reaches the same glibc `expf` as the C++.
- tinymind's `examples/iris` (4-8-3, ReLU hidden, sigmoid outputs, 30000 steps) is
  ported and bit-exact too: stdout and all three CSVs.
- The same xor example in **Q8.8** (`xor --format q8.8`, `i16` storage) is also
  bit-exact. tinymind ships xor only in Q16.16, so the Q8.8 reference is the C++
  example built with both bit counts in `xornet.h` set to 8; the compare script does
  that edit in its temp copy.
- Ported against the tinymind commit in `TINYMIND_REF` (verified byte-identical there).

## Floating point


Floating point (2026-11-09): `Scalar` (was `Fixed`) is implemented for `f32`/`f64` (`pow2_neg`
by exact halving, `div_int` = `self / n as $t`, as the C++ `value /= n`), so every
network type is generic over them; `Tanh`/`Sigmoid` for floats come from
`impl_float_activations!` (tanh, `1/(1+exp(-x))`, derivatives `1-y*y`,
`y*(1-y)`, as tinymind's float example and `nn_unit_test.cpp` write them) with
feature `std` (system libm: bit-exact with the C++ on glibc) or the optional
`libm` feature/dependency (`no_std`, not bit-exact; `all(libm, not(std))`, so
`--all-features` uses std). tinymind ships no float transfer-function bundle:
the library templates plus user specializations are its float path, copied
unchanged into `scripts/cpp/float_mlp.cpp` (needs `<new>` and
`fixedPointTransferFunctions.hpp` for `ZeroToleranceCalculator`; built with
`-ffp-contract=off`). The bundle's rates are 0.15/0.5/0.1; the Rust default rates
stay 1/4, 1/2, 1/16 for every type, so tests set them. `tests/float_mlp.rs`
(feature std) matches every step of five configs (f64/f32; 1-2 hidden layers;
tanh/ReLU; sigmoid/linear) on the first run. The f32 runs differ between glibc
2.39 (here) and CI's newer glibc (2.41 made tanhf/expf correctly rounded; f64
matched): so the committed golden holds only the f64 lines, and
compare-with-cpp.sh runs the test with `TINYMIND_FLOAT_MLP_CPP` = that host's C++
output to compare every line live (KEEP_CPP_OUTPUT copies only f64 lines); plants (tanh derivative as
(1-y)(1+y), div_int via reciprocal, sigmoid +eps/4) fail it. panic-never runs
float networks with `libm` (M0+ soft float and M4F). tinymind's
`AdamOptimizerFloat`/`RmsPropOptimizerFloat` are ported as `AdamFloat` /
`RmsPropFloat` (src/optimizer.rs, `impl_float_optimizers!` for f32 and f64;
pub f64 hyperparameters with the C++ values as `Default`; casts exactly as the
C++: `(beta as T) * m`, `((1 - beta2) as T) * g * g`, `m / ((1 - pow(beta, t)) as
T)`, `sqrt` in f64 then cast; pow/sqrt from std or libm via `float_math`). The C++
program attaches them as nn_unit_test.cpp does (bundle + `OptimizerPolicyType`
typedef), needs `-DTINYMIND_ENABLE_FLOAT=1`, and gives those runs learning rate
0.01 (0.15 saturated the f32 tanh run and killed a ReLU one). Four more configs,
all bit-identical live; plants (Q-style t<100 cut-off, beta1*m in f64, epsilon
outside the division, decay swapped) fail. The
value-type trait was renamed `Fixed` -> `Scalar` at Dan's request (2026-11-09):
`Fixed` stays as a `#[deprecated(since = "0.2.0")]` subtrait with a blanket
impl for every `Scalar`, so `V: Fixed` bounds compile with a warning (doctest on
`Fixed`; checked from an outside crate). Implementors of `Fixed` break, so the
next release is 0.2.0, not 0.1.6.
